1. 專案概覽

1.1 專案目標與成功指標

本專案以免費、開源、本機優先方式，將輔翼 ERP (FlapsErp，Electron 桌面版，安裝於 C:\SYSTEM_PROGRAM_DIRECTORY\FlapsErp) 與電商系統打通，實現訂單、庫存、客戶、出貨與退貨資料的自動化對接，減少人工重複輸入與對帳。

1.2 範圍與邊界

納入 (In Scope)

  • FlapsErp 與電商系統之間訂單、庫存、客戶、出貨、退貨資料的自動讀取與寫入。
  • 三層對接模式：優先 API/服務層；次選 OpenRPA 桌面 UI 自動化 (winax/COM)；最後資料庫直讀做補強對帳。
  • 繁體中文編碼轉換 (內部 UTF-8 ↔ 電商系統 CP950/Big5，透過 iconv-lite)。
  • OpenRPA + PowerShell + Windmill (原生二進位部署，不含 Docker)。
  • 幂等控制（穩定業務鍵：訂單／出庫單／退貨單編號等）、雙端對帧、異常佇列與人工複核。
  • 開發/測試/生產環境建置；發布、監控、備份、回滾 SOP。

排除 (Out of Scope)

  • 電商系統端原始程式碼修改或逆向工程；微服務、Kubernetes、Kafka、向量資料庫、複雜事件架構。
  • 商業 RPA 授權 (UiPath/Automation Anywhere 企業版)、Docker 容器化。
  • 非訂單/庫存/客戶對接之其他業務模組；電商前端頁面與行銷功能。

10. 部署與維運計畫

10.1 環境與發布流程

  • 開發環境 (DEV)：開發者本機，Windows 10/11，FlapsErp 測試版安裝於 C:\SYSTEM_PROGRAM_DIRECTORY\FlapsErp。
  • 測試環境 (UAT)：與生產同規格，Windows 10/11，FlapsErp 穩定版，OpenRPA 設計師 + 執行端。
  • 生產環境 (PROD)：Windows 10/11 或 Windows Server，16 GB RAM，4 核 CPU，固定 IP，FlapsErp 發行版，OpenRPA 無人值班執行端。
  • 三環境嚴格隔離，生產資料不得回填至開發環境，除非經過敏感資料遮蔽。
  1. 開發完成後於 DEV 環境進行單元測試與程式碼審查。
  2. 部署至 UAT 環境，執行整合測試、效能測試、安全測試。
  3. UAT 驗收通過後，建立發行版本 (版本號格式 vMajor.Minor.Patch，例如 v1.0.0)。
  4. 在 PROD 環境備份現行版本與資料。
  5. 於離峰時段 (每日 02:00~06:00) 部署至 PROD，Windmill 排序啟動對接作業。
  6. 部署後執行冒煙測試，確認核心功能正常。
  7. 若發現 Severity 1 缺陷，立即觸發回滾程序。

11. 系統流程最佳化建議

  • 對接模式優先級：優先採用模式 A (API/服務層)，因為穩定、快速且易監控；僅在電商系統無 API 時才啟用模式 B (OpenRPA 桌面自動化)；模式 C (資料庫直讀) 僅作每日對帧補強，避免直接寫入電商系統資料庫。
  • 編碼統一：FlapsErp 內部採用 UTF-8，與電商系統交換時透過 iconv-lite 轉換 CP950/Big5，建立標準編碼轉換函式庫，避免各模組重複實作。
  • 幂等與對帧：所有對接交易以「穩定業務鍵」（訂單／出庫單／退貨單編號等）為幂等鍵（時間戳僅作稽核欄位），每日 02:00~06:00 自動雙端對帧，差異進入待人工複核佇列，降低資料不一致風險。
  • RPA 主機穩定：關閉睡眠與螢幕關閉，固定視窗解析度 (1920×1080, 100% 縮放) 以提升 OpenRPA 元素辨識穩定性；每週重新啟動主機一次釋放記憶體。
  • 智能化漸進：Phase 1 優先實作基礎對接與對帧；Phase 2 可考慮加入 Isolation Forest 輕量異常偵測，標記高風險筆錄，避免初期即引入複雜 AI 架構。
  • 文件即程式碼：架構圖、介面矩陣、RPA 工作流與 PowerShell 腳本均納入版本控制，與程式碼同步版本，避免文件與實作脫節。
  • 電商訂單狀態機對映：建立電商系統訂單狀態 (待付款/已付款/已出貨/已完成/退貨中/已取消) 與 FlapsErp 訂單狀態的標準對映表，避免狀態語意不一致導致對帧錯誤。

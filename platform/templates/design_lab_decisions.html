DEC-DL-01 ▸ 暗色優先主題分層

決策記錄（八欄）
需求每日高頻使用的工具介面；淺色長時使用刺眼、層級辨識差。
選擇暗色優先（dark-first）＋玉山綠 accent；以獨立主題層（ui-v2.css）覆蓋全部語義 Token，不散改元件。
原因2026 專業工具主流（Linear／Vercel／Grafana／Supabase）皆暗色優先；集中覆蓋可一次修正殘留淺色背景。
替代方案① 淺色優先；② 雙主題切換（需狀態儲存→不符零 JS）；③ 逐元件改色（散落難維護）。
優勢層級清楚、長時間舒適；元件不需個別修改；淺色媒體查詢仍保有後備。
缺點列印與淺色需求須另驗（S4 黑白可讀列入檢查表）。
證據ui-v2.css（完整語義 Token 覆蓋）；護欄測試比對色值 ∈ 設計系統調色盤。
驗證R5 視覺輪：對比檢查＋逐頁走查；設計 Token 頁列出兩主題值。

DEC-DL-02 ▸ 零 JS 互動模型

決策記錄（八欄）
需求高效能、易維護、跨裝置的互動；禁用耗費效能的 JS 工具鏈。
選擇互動僅用 CSS 與伺服器渲染：表單 POST＋PRG、:target 面板、details 披露、:focus-visible 焦點。
原因零 JS＝零啟動成本、零 XSS 面、無限裝置相容；金額與權限一律伺服器端 fail-closed。
替代方案① 少量 JS 增強（增加供應鏈與 CSP 風險）；② SPA（背離憲政約束）；③ HTMX 類工具（同屬 JS 依賴）。
優勢效能穩定（無 hydration）、可及性直接由語義 HTML 承接、測試面簡單（HTTP 層可全覆蓋）。
缺點複雜互動（拖曳、即時篩選）不可行——以流程設計迴避或明示限制。
證據護欄掃描：全模板腳本標籤數為 0、內聯樣式屬性數為 0；頁面矩陣全綠。
驗證R1 靜態輪＋R6 端到端輪；所有任務鏈以純瀏覽器（無 JS）完成。

DEC-DL-03 ▸ 體驗室 Gate=ROLE_MANAGE

決策記錄（八欄）
需求體驗知識需被驗收與入門使用，但操作者層不得見開發文件（受眾分層 IA）。
選擇體驗室十頁設 ROLE_MANAGE 閘（伺服器端逐頁檢查）；導覽僅對管理者顯示入口。
原因「隱藏」不等於「保護」——直接輸入 URL 亦須 403；管理者與技術人員是規格的維護者。
替代方案① 全體可見（污染操作者資訊）；② 僅文件（無展示與回歸基準）；③ 導覽隱藏但不加閘（可繞過）。
優勢展示與保護兼得；與治理頁同一權限模型，無新增角色。
缺點新人訓練期間需管理者陪同瀏覽。
證據route 對帳（manifest↔api.rs 雙向）、角色矩陣測試（admin 200／store、finance 403／visitor 303）。
驗證R4 權限輪；體驗室專屬測試套件。

全端介面鏈（L1–L6）

「全端」不只畫面（S1–S9），也含後端介面；每層都有契約與驗證，禁止跨層假設。

介面鏈分層與驗證
層 範圍 契約要點 驗證
L1 呈現模板／CSS／瀏覽器EC-1..EC-10；零 JS；Token；八態護欄、頁面矩陣、無障礙
L2 HTTP路由、狀態碼、標頭、CSRF動詞語義、錯誤碼、安全標頭、快取政策API 契約測試、curl
L3 應用handler → 用例授權、輸入驗證、冪等、交易邊界整合測試、故障注入
L4 領域金額、分錄、狀態機i64 minor、借貸平衡、狀態轉移單元與 property 測試
L5 資料schema、索引、WAL遷移、約束、索引、備份與還原遷移測試、EXPLAIN、演練
L6 運維日誌、健康、備份、更新可觀測、退出碼、復原健康檢查、runbook

工具組體驗契約（TT-1..TT-5）

CLI、腳本與管線也是介面；「工具包不精緻」的另一半在此把關。

工具組契約
ID 契約 規則
TT-1一致 help每個子命令有 --help、用法、範例、退出碼說明
TT-2退出碼語義0 成功；非 0 失敗；UNKNOWN 明確（不得以 0 冒充）
TT-3雙模式輸出人類可讀＋--json 機器可讀；欄位穩定
TT-4無破壞預設破壞性動作需 --yes 或 dry-run；預設不覆蓋
TT-5每台機器通用偵測環境（CPU／GPU／路徑／相依）；禁寫死本機規格

契約使用規則

  • 新頁面不得在規格缺席時新增；先在規格登錄契約對照。
  • 不適用（N/A）必須寫理由（例：靜態頁無 POST → EC-4 不適用）。
  • 任一層介面變更，必須同步契約文件與測試；上層不得假設下層已驗證（縱深防禦）。

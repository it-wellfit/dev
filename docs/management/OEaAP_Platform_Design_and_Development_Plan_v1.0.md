# 輔翼 ERP 自動化平台開發計畫 — 新一代優化版

## 1. 專案概述

### 1.1 專案目標

建立一套 **不依賴外部 ERP 供應商**、**以自動化為核心**、**具備 RPA + AI 功能的開源 ERP 替代方案**，最終實現 **所有資訊系統的整合與優化**。

### 1.2 產品定位

**名稱**：Open Enterprise Knowledge & Action Platform (OEaAP)
**版本**：v2.1.0
**基礎**：Wellfit 現有 7-crate Rust 工作區 + 新模組擴展
**部署方式**：原生二進位 (Windows/Linux/macOS)，無 Docker，免費開源 (MPL-2.0)

### 1.3 核心價值

- **不依賴供應商**：自主開發所有核心功能，終止對 FlapsErp 等供應商的被動相依
- **漸進式演進**：從輔助工具出發，逐步取代被動依存的 ERP 功能
- **智能自動化**：基於 RPA + AI + 知識圖譜，實現高自動化率
- **效能至上**：基於 Rust 高效能、零依賴、極小開發週期
- **安全性強**：本機優先、開源透明、安全第一

### 1.4 成功指標 (KPI)

| 指標 | 目標 | 驗證方式 |
|------|------|------------|
| ERP 功能覆蓋率 | ≥ 95% (原 ERP 核心功能) | 功能測試，模擬交易場景 |
| 自動化率 | ≥ 85% (人工互動頻率) | 監控日誌分析 |
| 延遲控制 | API ≤ 2s，RPA ≤ 10s | 負載測試 |
| 可用性 | ≥ 99.5% (月平均) | 監控日誌，排除事件記錄 |
| 違規成本 | ≤ 10% (相對於 FlapsErp) | 成本效益分析 |
| 開發週期 | 3-6 個月核心上線 | Sprint 迴圈驗證 |

## 2. 技術架構

### 2.1 基本理念

**漸進式 ERP 取代策略**：
1. **Stage 1 (0-3 個月)**：輔助工具 → 增強自動化
2. **Stage 2 (3-6 個月)**：協同操作 → 部分功能取代
3. **Stage 3 (6-9 個月)**：智慧協作 → 核心功能取代
4. **Stage 4 (9-12 個月)**：完全取代 → 全系統整合

### 2.2 技術棧

| 層次 | 技術 | 工具 | 依賴性 |
|------|------|------|------------|
| **核心層** | Rust 2021 + 7-crate Wellfit | Cargo, VS Code | 底層效率，零依賴 |
| **自動化層** | OpenRPA + PowerShell | Node.js + TypeScript | RPA 桌面自動化 |
| **排序層** | Windmill 原生二進位 | sc.exe (Windows) | 定時觸發，零 Docker |
| **介面層** | Winax/COM + ffi-napi | Windows ActiveX | 本機元件呼叫 |
| **儲存層** | SQLite + AES-256 加密 | 本機檔案 | 本機優先 |
| **AI/知識層** | Isolation Forest + 知識圖譜 | Python/scikit-learn | 異常偵測，決策支持 |

### 2.3 模組架構

```
OEaAP 模組劃分：
├── Core (wellfit_core 擴展)
│   ├── MDM (Master Data Management) → 替代 FlapsErp 基本資料
│   ├── 契約引擎 (ColumnContract 擴展) → 取代 FlapsErp 進銷存契約
│   ├── 驗證框架 (新增) → 取代 FlapsErp 驗證邏輯
│   └── 安全框架 (新增) → 取代 FlapsErp 安全控制
├── Assistive Tools (新增)
│   ├── 資料轉換助手 (對接 API ↔ CSV) → 取代手動轉換
│   ├── 報表生成器 (HTML/PDF) → 增強 FlapsErp 報表輸出
│   └── 異常偵測儀表板 (AI) → 取代 FlapsErp 查詢功能
├── Automation (wellfit_* 擴展)
│   ├── Procurement Automation (Shopee 擴展) → 取代 FlapsErp 採購模組
│   ├── Inventory Management (wellfit_reports 擴展) → 完全取代 FlapsErp 庫存
│   ├── Payment Processing (BankPay 擴展) → 取代 FlapsErp 應付憑單
│   └── Order Management (wellfit_mtrix 擴展) → 完全取代 FlapsErp 訂單
├── Integration (新增)
│   ├── ERP 協同層 (取代 FlapsErp) → 支援多 ERP 協作
│   ├── CRM 整合層 (新增) → 整合客戶資料
│   └── SCM 整合層 (新增) → 整合供應鏈
├── Orchestration (Windmill 擴展)
│   ├── 任務排程器 → 取代 FlapsErp 作業排程
│   ├── 斷路器設計 → 取代 FlapsErp 容錯機制
│   └── 監控告警 → 增強 FlapsErp 監控
└── Security (新增)
    ├── 身份認證 (Keycloak 整合) → 取代 FlapsErp 認證
    ├── 授權控制 (RBAC/ABAC) → 增強 FlapsErp 權限
    └── 稽核框架 (新增) → 取代 FlapsErp 稽核
```

## 3. 優化策略

### 3.1 漸進式取代方法

#### 3.1.1 階段策略

| 階段 | 週數 | 核心目標 | 交付成果 |
|------|------|----------|------------|
| **Stage 1** | 0-3 | 輔助工具導入 | - 資料轉換助手<br>- 報表生成器<br>- 異常偵測儀表板 |
| **Stage 2** | 3-6 | 協同操作 | - 進貨訂單自動化<br>- 出庫單處理自動化<br>- 應付憑單自動化 |
| **Stage 3** | 6-9 | 智慧協作 | - 客戶資料自動化<br>- 庫存同步自動化<br>- 異常自動處理 |
| **Stage 4** | 9-12 | 完全取代 | - ERP 協同操作<br>- 多 ERP 整合<br>- 智能決策支持 |

#### 3.1.2 實作策略

1. **保留 FlapsErp 階段**：利用 FlapsErp 現有 API/COM 物件進行早期階段
2. **重寫核心功能**：如需功能變更，則重寫 Rust 模組
3. **逐步導入 RPA**：從簡單的資料處理開始，到複雜的業務邏輯
4. **AI-驅動優化**：導入智能異常偵測和決策支持
5. **無縫切換**：確保在穩定階段完成後，可進行無縫遷移

### 3.2 績效優化策略

#### 3.2.1 Rust 核心優化

- **零依賴**：所有依賴均打包於二進位中
- **高效資料結構**：採用 Rust 最佳實踐
- **編譯期檢查**：確保類型安全性和記憶體安全
- **零 garbage collection**：靜態分配

#### 3.2.2 RPA 優化

- **事件驅動模式**：減少等待時間
- **並行處理**：多 RPA 工作流並行執行
- **智能重試**：基於指數退避策略
- **資源監控**：防止 RPA 記憶體洩漏

#### 3.2.3 儲存優化

- **SQLite 本機優先**：極致效能，低延遲
- **幂等控制**：確保交易安全性
- **AES-256 加密**：敏感資料保護
- **增量備份**：減少備份時間

### 3.3 安全策略

#### 3.3.1 本機安全

- **Application Control**：僅允許信任的二進位
- **Windows Security**：整合 Windows 認證機制
- **沙盒化**：隔離 RPA 工作流
- **日誌保護**：敏感資料遮蔽

#### 3.3.2 資料安全

- **Encryption at Rest**：所有儲存資料加密
- **Encryption in Transit**：TLS 1.2+ 加密
- **Access Control**：RBAC + ABAC 雙重控制
- **Audit Trail**：完整稽核日誌

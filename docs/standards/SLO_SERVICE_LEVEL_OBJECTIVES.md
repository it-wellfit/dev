# SLO — 服務層級目標（AuxBridge 整合工作台）

> 版本：v1.0（provisional）｜制定：2026-11-17｜制定者：AI 代理（architect 判斷）＋使用者授權「專業判斷代行」
> 複核條件：營運滿 3 個月實績後複核；或部署頻率/使用者規模變動 > 50% 時即時複核
> 關聯：計畫 1793782615513 §10.1（錯誤預算）、docs/ops/INVENTORY.md、docs/ops/DRILL_LOG.md

## 1. 輸入參數（專業判斷推導）

| 參數 | 裁定值 | 推導依據 |
|---|---|---|
| 部署頻率 | 10 次/月（活躍期上限） | 觀測史：W11→W12→W12b 迭代期實際部署節奏；穩態 2-4 次/月，取上限保守預算 |
| 單次事故可接受停機 | 30 分鐘 | 回滾演練實測 RTO 約 4 分鐘（staging.db 損壞→還原→/health 恢復）；30 分 = 7.5x 餘裕 |
| 影響使用者 | 內部團隊 5-20 人 | RBAC 種子角色 4 類（admin/finance/pos/store）＋單機部署；非對外服務 |
| 計畫性維護 | 不計入 SLO | deploy.ps1 為 health-gated 快速切換（實測 <1 分鐘），安排於離峰執行 |

## 2. SLO 裁定

| 指標 | 目標 | 錯誤預算 |
|---|---|---|
| 可用性（月度） | 99.5% | 30 天 x 0.5% 約 216 分鐘/月（非計畫停機） |
| 健康探針成功率 | 99.9%（/health、/ready） | 約 43 次失敗/月 |
| 頁面 p95 延遲 | 650ms 以內（實測基線 504ms） | 連續 5 分鐘超標即告警 |

> 為何不是 99.9%：單機 SQLite + 內部使用者架構下，99.9%（43 分/月）需叢集化才能可靠達成——違反右 sizing。99.5% 現架構可穩定達成；上雲/叢集化後複核上調。

## 3. 錯誤預算政策

1. 預算耗盡（當月非計畫停機 > 216 分鐘）→ 凍結功能發布，僅允許修復與可靠性改善。
2. 每次事故 → docs/ops/POSTMORTEM_TEMPLATE.md 複盤 + 關聯 ADR。
3. 版本發布附版本演進評分卡（計畫 §10.4），證明「優於前版」。
4. 預算剩餘 < 25% → 提升告警敏感度、暫停非必要重構。

## 4. 量測方式

- 停機判定：/health 非 200（自動探測或人工記錄於 DEPLOY_LOG.md）。
- 資料來源：server stderr JSON 日誌（AUXBRIDGE_LOG_FORMAT=json）＋ DEPLOY_LOG.md。
- 月度報告：每月 1 日由 Release Owner 彙整前月數據（可用性、事故數、MTTR、預算消耗）。

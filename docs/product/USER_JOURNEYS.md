# User Journeys — FlapsErp RPA 支援線核心使用者旅程

> 版本：v1.0｜日期：2026-11-03｜狀態：Active
> 對應需求見 `docs/product/PRD.md` §2；介面基準為 `web/index.html`（零 JS）。
> 每個旅程同時描述理想情境與失敗情境（含恢復方式）。

## 旅程 1：帳務登帳（對應 FR-003／FR-005）

**Persona**：營運人員（每日多次）
**起點**：進入工作台 → 目的：完成一筆帳務登帳

### 理想情境

| 步驟 | 使用者操作 | 系統回應 |
|------|-----------|----------|
| 1 | 導航點擊「新增交易」 | `:target` 切換至表單分區，焦點可達（鍵盤 Tab） |
| 2 | 選擇會計科目、輸入金額、借貸別、幣別、摘要、日期 | 原生表單驗證即時回饋（`:user-invalid` 紅框＋hint） |
| 3 | 點擊「建立交易」（POST /transactions） | 伺服器驗證（日期未來、負數、借貸別、科目存在）→ 寫入 SQLite（冪等 UUID）→ 寫入 audit_log |
| 4 | — | 302 Redirect 至交易清單（PRG），顯示成功回饋 |

### 失敗情境

| 失敗 | 系統行為 | 恢復方式 |
|------|----------|----------|
| 必填欄位缺漏 | 原生驗證阻擋提交，欄位級訊息 | 使用者依 hint 修正 |
| 未來日期／負數金額 | 伺服器回 4xx＋欄位錯誤訊息（問題＋原因＋處理方式） | 表單保留輸入值（伺服器渲染），修正後重送 |
| 重複提交 | 冪等 UUID 印記擋下（INV-04），僅回傳首次結果 | 無需處理 |
| 資料庫鎖定 | WAL＋busy_timeout 5000ms（INV-03）；逾時回明確錯誤 | 稍後重試；持續失敗見 troubleshooting-runbook |
| 伺服器錯誤 | 錯誤卡：「無法建立交易／可能原因：…／請重試或聯絡管理員」 | 重試；audit_log 記錄失敗事件 |

### 完成條件

交易存在於清單、audit_log 含 `TRANSACTION_POSTED` 事件、使用者看到成功回饋。

## 旅程 2：交易查詢與覆核（對應 FR-007）

**Persona**：財務審計員（每週）

1. 導航「交易」→ 清單載入（Loading → 資料 / Empty / Error 三態之一）。
2. 以日期區間＋狀態篩選；分頁瀏覽（limit/offset，參數化查詢）。
3. 點開單筆交易檢視明細（借貸平衡、items）。
4. **失敗情境**：查詢逾時 → 錯誤卡＋「重試」；無權限 → 明確 403 訊息（非空白頁）。

完成條件：審計員能在 30 秒內定位任一筆交易及其稽核紀錄。

## 旅程 3：AI 決策覆核（對應 FR-008）

**Persona**：營運人員＋財務覆核者

1. 觸發事件（如異常交易）→ 規則引擎預驗證 → AI 評分（非同步，不阻塞登帳）。
2. score < 0.3：自動通過（記錄）；0.3–0.7：進入「待覆核」，清單標示 badge；≥ 0.7：自動拒絕＋告警。
3. 覆核者在「AI 決策」清單看到建議＋來源證據＋信心分數，人工核准或駁回；結果回饋記錄於 audit_log。
4. **失敗情境**：AI 服務不可用 → 介面顯示「部分不可用」（Degraded 態，`#ai-decisions`），規則引擎不受影響，登帳照常；AI 禁區操作（金額修改、權限變更、作廢、科目變更、結帳）永不經 AI。

完成條件：每筆 AI 建議的處置（通過／覆核／拒絕）皆可追溯至 audit_log。

## 旅程 4：介面首次進入（對應 FR-004／NFR-005）

1. 使用者首次開啟工作台 → 預設顯示「總覽」分區（`:target` 無錨點時由 `:has()` 回退）。
2. 後端未介接時：KPI 顯示「—」（未知），清單顯示 Empty 態＋下一步動作連結；不以範例數字冒充真實資料。
3. 服務不可用：錯誤卡（問題＋可能原因＋處理方式）＋「重試」。
4. 鍵盤使用者：skip-link → 主要內容；Tab 順序：導航 → 分區 → 表單欄位。

完成條件：新使用者不需說明文件即可找到「新增交易」入口。

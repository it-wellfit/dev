## 分級說明

- **P0**：影響大＋成本低 → 立即償還（下一迭代）
- **P1**：影響大＋成本高 → 排程償還（明確版本／日期）
- **P2**：影響小＋成本低 → 順手償還（touch-and-fix）
- **P3**：影響小＋成本高 → 記錄接受（每季重審）

## 償還排程

採 **20% 容量法則**——每迭代保留 20% 工時償還 P0/P1 技術債；P2 採 touch-and-fix；連續兩迭代未消化 P0 → 升級為阻塞項目，暫停新功能。

## 治理節奏

| 節奏 | 活動 |
|---|---|
| 每迭代 | 技術債 triage：新債登記、P0 清點 |
| 每月 | 償還進度對帳（登記簿狀態 vs 實際提交） |
| 每季 | 全量重審：P3 是否仍成立、20% 容量是否兌現、指標儀表板校準 |

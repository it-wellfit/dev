1. 管理層摘要

1.1 專案定位與核心發現

輔翼 ERP（FlapsErp v0.0.4）為閉源 Electron 桌面應用（Chromium + Node.js 16.16.0，ia32 32-bit），透過 winax/ActiveX 與後端 ERP 系統（Java JSP + COM 物件）通訊。經逆向解構與基線量測，確認核心效能瓶頸為 「同步 COM 呼叫阻塞 Electron 主執行緒」 與 「缺乏快取與生命週期管理」，並疊加 32-bit 位址空間上限（約 2GB） 與 同步檔案 I/O。

由於原廠程式為閉源且受 bytenode 保護，我方 無法直接修改原廠程式碼。本專案採 雙軌策略： - A 線（向原廠）：透過正式提案包（OQ-F1/F2）回報需求與建議（64-bit、非同步 IPC、憑證模式、RDA API 規格等），依賴原廠回覆； - B 線（我方環境）：透過 Utility Process、非同步 IPC、表單 LRU 快取、COM 物件池、批次 COM 呼叫、Wellfit 批次外移、flapserp:// 排程、config.ini 調優，可立即執行。

1.2 現況摘要（✔ 已驗收）

  • Phase 1（量測與軌道建置）：全部 7 項任務（T-101 ~ T-107）驗收通過，符合退出條件。
  • 整體進度：約 30%（四階段中第一階段完成）。
  • 風險燈：🟡 黃（EULA/授權邊界未明、32-bit 記憶體上限、元件漂移）。
  • 下一階段：Phase 2 批次上線試行，排程於 2026-11-10 至 11-16，尚未開工。

2. 專案背景與目標

2.1 專案來源與定位

FlapsErp（輔翼 ERP）為輔翼系統開發的桌面應用程式，版本 v0.0.4，安裝檔 SHA-256：DC77C024629629149842714B8F599565DB04121AF043F5517450BAA5F0AE79B6。應用執行環境為 Electron (Chromium + Node.js 16.16.0)，打包架構為 ia32 32-bit，前端為 Vue 2.6.12 + Bootstrap 5.0.1，後端為 Java JSP（RDAPortal.jsp，XML 協定 com.flaps.Module.RDA.TGetModuleInfo），元件層為 Delphi/C++ COM DLL（midas.dll、MReportViewer.dll、POSMachineController.dll 等）。

2.2 專案目標

將 FlapsErp 效能提升至可接受水準，具體包括： - 消除 UI 凍結 - 降低記憶體增長 - 縮短表單載入與啟動時間

4.2 COM 呼叫延遲基線（1000 迴路，✔）

6.1 整體策略：雙軌並行

6.2 三階段實施路徑

Phase 1 — 立即見效（1–2 週，✅ 已完成）

  1. COM 呼叫移至 Worker/Utility Process
  2. 同步 IPC → 非同步 IPC (ipcRenderer.invoke + Promise)
  3. 啟用硬體加速
  4. 表單資料快取（LRU，TTL 5 分鐘）

Phase 2 — 架構優化（3–6 週，⏳ 下期）

  1. COM 物件池 + 生命週期管理（上限 50，WeakRef 自動釋放）
  2. 批次 COM 呼叫（合併屬性讀取，減少 IPC 往返 80%+）
  3. 資料序列化優化（structured clone / transferable）
  4. 背景分頁節流 (backgroundThrottling: true)

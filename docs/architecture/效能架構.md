## P2 軟體架構槓桿

### P2.1 資料庫層（SQLite WAL）

| 優化 | 說明 | 預期效益 |
|------|------|----------|
| WAL 模式 | 讀寫並行；讀取不阻塞寫入 | 併發查詢吞吐提升 |
| `synchronous = NORMAL` | 平衡安全與效能 | 寫入延遲降低 |
| `cache_size = -64000` | 64 MB 快取 | 熱資料命中率提升 |
| `temp_store = MEMORY` | 臨時表格記憶體化 | 中間計算加速 |
| `busy_timeout = 5000` | 鎖定等待 5 秒 | 併發衝突減少 |
| 參數化查詢 | 無字串拼接；預編譯語句 | SQL 注入防護＋執行計畫快取 |
| 熱路徑索引 | `idx_transactions_date`、`idx_transactions_status` 等 | 查詢過濾加速 |

### P2.2 應用程式層（Axum + Tokio）

| 優化 | 說明 | 預期效益 |
|------|------|----------|
| 非同步 I/O | Tokio 執行緒池；阻塞工作卸載至 `spawn_blocking` | 併發連接數提升 |
| 請求逾時 | `AgentBuilder::timeout()`；30 秒預設 | 防止無限等待 |
| 連接重用 | `ureq::Agent` 連接池 | TLS 握手開銷降低 |
| 零 JS 前端 | 無前端建置鏈；靜態 HTML/CSS/SVG | 首次載入 < 1 秒 |
| 服務端渲染 | Askama 模板；編譯時檢查 | 首次畫面繪製快速 |

### P2.3 前端層（零 JavaScript）

| 優化 | 說明 | 預期效益 |
|------|------|----------|
| 無 JavaScript 建置鏈 | 無 Node.js；無 Webpack/Vite；無 bundler | 建置時間為零；部署單一執行檔 |
| CSS `:target` 分區 | 無 JS 路由切換 | 頁面切換無網路請求 |
| CSS `:has()` 導航高亮 | 無 JS 事件監聽 | 互動回饋即時 |
| SVG 圖表 | 伺服器端生成；內嵌 HTML | 圖表載入無額外請求 |

## P3 硬體架構槓桿

| 項目 | 建議規格 | 說明 |
|------|----------|------|
| 儲存裝置 | SSD（固態硬碟） | SQLite WAL 模式對隨機寫入敏感；SSD 顯著降低延遲 |
| 記憶體 | ≥ 4 GB | SQLite 快取（64 MB）＋應用程式記憶體；Windows 桌面環境 |
| CPU | 2 核心以上 | Tokio 非同步執行緒池；並行查詢處理 |
| 網路 | LAN（銀行端連接） | E.Sun 安控元件連接；本地網路延遲 < 5 ms |
| 作業系統 | Windows（原生二進位部署） | sc.exe 服務；無 Docker 容器開銷 |

### P3.1 部署目錄（WDAC 合規）

| 目錄 | 用途 | 說明 |
|------|------|------|
| `%LOCALAPPDATA%\Temp\dev-target` | 建置產物 | 桌面應用程式控制原則阻擋時的替代目標目錄 |
| `%LOCALAPPDATA%\Temp\wellfit-target` | Wellfit 建置產物 | 同上 |
| `C:\Program Files\FlapsERP\` | 生產安裝 | 需部署授權（🔒） |

## P4 量測與基準協定

### P4.1 量測方法學

1. **≥ 5 次重複取中位數**：單次測試受系統雜訊影響；中位數消除極端值。
2. **修正 CDP 探測器**：驗證 `/json/version` 之 `UserAgent`/`Product` 欄位，避免 Edge 9222 誤判為瀏覽器問題。
3. **MTRIX 管線多次執行**：確保效能數據具備重現性；CI 中每次推送皆執行。
4. **COM 延遲變異（取樣）**：2026-11-03 P50/P95/P99 `0.2636/0.3884/0.4740` ms；2026-11-06 `0.1869/0.2634/0.3394` ms；2026-11-11 `0.1736–0.1882/0.2069–0.3171/0.2405–0.4467` ms（四次取樣）；變異大，比較前需多次樣本。

### P4.2 監控指標（建議）

| 指標 | 來源 | 警示閾值 |
|------|------|----------|
| 交易處理延遲 | 應用程式日誌（span 計時） | P99 > 50 ms |
| 資料庫查詢延遲 | SQLite `EXPLAIN QUERY PLAN` | > 10 ms |
| 併發連接數 | `sessions` 表計數 | > 50 |
| 錯誤率 | `audit_log` 錯誤事件 | > 0.1% |
| 系統啟動時間 | 處理序啟動時間戳 | > 2 秒 |

## P5 軟硬體協同解決效能問題

| 效能問題 | 軟體解法 | 硬體解法 | 預期改善 |
|----------|----------|----------|----------|
| 查詢緩慢 | 參數化查詢；熱路徑索引；WAL 模式 | SSD；更多記憶體（快取命中率） | 3–10× |
| 併發衝突 | `busy_timeout`；寫入交易 ≤ 50 ms；連接池 | 多核心 CPU；更快 SSD | 2–5× |
| 首次載入慢 | 零 JS 前端；靜態 HTML/CSS/SVG；CDN（未來） | SSD；更快網路 | 5–10× |
| AI 決策慢 | 風險分閘門；僅對高風險交易人工覆核 | 更快 CPU；本地推論（未來） | 2–3× |
| 匯入緩慢 | 批次處理；預檢 5,000 列預算 | SSD；更多記憶體 | 5–10× |

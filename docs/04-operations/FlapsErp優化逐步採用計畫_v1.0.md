# FlapsErp 優化逐步採用計畫 v1.0
# 從實驗室到同仁工作機：每一步都由同仁自己確認「沒問題」才進下一步

> 日期：2026-11-13｜狀態：Draft（待同仁同意）
> 核心：**同仁不信任是最大的風險。唯一解決方法是讓他們親身驗證，而不是告訴他們數據。**
> 原則：每個階段結束時，由**使用它的同仁自己決定**是否進入下一階段。任何人說「不」就停。

---

## 概覽：五個階段，每一階段都有退路

```
Stage 0｜代理的測試環境（不是同仁的機器；零風險）
    ↓ 同仁看到數據，說「OK 可以在我機器上試」
Stage 1｜一位自願者的工作機（真實工作環境）
    ↓ 該同仁用 3-5 天後說「沒問題」
Stage 2｜2-3 位不同角色同事的工作機
    ↓ 每位都用 1 週後說「沒問題」
Stage 3｜部門全部機台
    ↓ 部門主管簽核
Stage 4｜組織全面部署
```

**任何階段任何人說「不」→ 立即回滾該機台 → 不影響其他機台 → 回到上一階段改善。**

---

## Stage 0：代理的測試環境

### 目的
在不影響任何同仁工作的前提下，驗證所有優化步驟可以正確執行。

### 機台
代理可以完全控制的機台（不是同仁的工作機）。

### 做什麼
1. 安裝 FlapsErp（如尚未安裝）
2. 執行 `flaps-optimize.ps1 -Action Full`
3. 確認所有步驟正確執行（或正確報告錯誤）
4. 啟動 FlapsErp → 確認可以登入和操作
5. 執行 App smoke：登入 → 選單 → 模組 → 報表 → 重啟 → 再登入
6. 執行 `flaps-safety-check.ps1` → 確認 10 PASS

### 完成條件

| 檢查 | 通過條件 | 誰確認 |
|---|---|---|
| 優化腳本執行無錯誤 | 0 errors | 代理 |
| FlapsErp 可以啟動和登入 | 可以 | 代理 |
| App smoke 全過 | 5 步全過 | 代理 |
| 安全檢查 PASS | 0 FAIL | 代理 |
| 回滾測試成功 | 回滾後 FlapsErp 仍正常 | 代理 |

### 退場條件
任何步驟失敗 → 修復 → 重試。**不進入 Stage 1** 直到全部通過。

### 產出
- `Stage0-results.md`：每個步驟的結果和截圖

## Stage 1：一位自願者的工作機

### 目的
在**真實工作環境**中驗證優化不影響日常作業。

### 機台
**自願同事的日常工作機**（不是測試機）。這位同事：
- 自願參與（不是被指派）
- 願意在優化後如果出問題就配合回滾
- 日常使用 FlapsErp 的頻率可以代表該角色

### 做什麼

| 天 | 動作 | 誰做 |
|---|---|---|
| Day 0 上午 | 備份 FlapsErp 設定 + config.ini + SHA256 | 代理 |
| Day 0 上午 | 記錄目前的系統狀態（RAM/CPU/磁碟） | 代理 |
| Day 0 上午 | **基線量測**：請同事做 3 個日常操作，用碼錶計時 | 同事 + 代理 |
| Day 0 下午 | 套用優化（`flaps-optimize.ps1 -Action Optimize`） | 代理 |
| Day 0 下午 | 重啟 FlapsErp → 同事確認可以登入和操作 | 同事 |
| Day 0 下午 | **優化後量測**：同樣的 3 個操作，用碼錶計時 | 同事 + 代理 |
| Day 0 下午 | 執行 `flaps-safety-check.ps1` → 給同事看結果 | 代理 |
| Day 1-4 | 同事正常使用 FlapsErp，代理每天檢查一次 | 代理 |
| Day 4 | **同仁確認**：這 4 天有沒有遇到任何問題？ | 同事 |
| Day 4 | **Go/No-Go 決定** | 同事 |

### 同事需要配合的事
- 正常使用 FlapsErp（不需要改變任何習慣）
- Day 0 下午花 10 分鐘做碼錶量測（3 個操作）
- Day 4 花 5 分鐘回答：「這幾天有沒有遇到任何問題？」

### Go/No-Go 條件

| 條件 | 結果 |
|---|---|
| 同事說「沒遇到問題」+ 安全檢查 0 FAIL + 碼錶沒有退步 > 10% | **GO** → Stage 2 |
| 同事說「有遇到問題」或安全檢查有 FAIL 或碼錶退步 > 10% | **NO-GO** → 回滾 → 回到 Stage 0 改善 |

### 回滾程序（如果 No-Go）
1. 執行 `flaps-optimize.ps1 -Action Rollback`
2. 重啟 FlapsErp
3. 請同事確認恢復正常
4. 記錄問題原因 → 回到 Stage 0 修復

### 產出
- `Stage1-daily-log.md`：每天的系統狀態和任何問題
- `Stage1-stopwatch.csv`：碼錶量測數據
- `Stage1-colleague-feedback.md`：同仁的回饋（原文）
- `Stage1-gonogo.md`：Go/No-Go 決定和理由

## Stage 2：2-3 位不同角色同事的工作機

### 目的
驗證優化在不同角色（不同 FlapsErp 使用模式）下都不影響工作。

### 機台
2-3 位同事的日常工作機，**各自代表不同角色**：

| 角色 | FlapsErp 使用模式 | 為什麼要測 |
|---|---|---|
| 財務人員 | 多分頁、報表、對帳 | 效能敏感度最高 |
| 物流人員 | 庫存查詢、POS | 不能延遲出貨 |
| 門市人員 | POS 交易、庫存查詢 | 不能讓客人等 |

> **不需要三個角色都測**。至少測 2 個不同角色，優先選擇使用 FlapsErp 最頻繁的角色。

### 做什麼

每位同事的操作與 Stage 1 完全相同：
1. Day 0：備份 → 基線量測 → 套用優化 → 確認
2. Day 1-4：正常使用 → 代理每天檢查
3. Day 4：同仁確認 → Go/No-Go

**每位同事獨立決定**。一位 No-Go 不影響其他位的結果，但**全部 Go 才進 Stage 3**。

### 額外量測（Stage 2 才做）

| 量測 | 目的 |
|---|---|
| 系統級 A/B（FlapsErp + 瀏覽器 + Office 併發） | 確認不影響其他程式 |
| 不同時段量測（早上/下午/下班前） | 確認全時段穩定 |
| 同事主觀評分（每個操作：更快/相同/更慢） | 收集體感數據 |

### Go/No-Go 條件

| 條件 | 結果 |
|---|---|
| 全部同事說「沒問題」 + 全部安全檢查 0 FAIL + 碼錶沒有退步 > 10% + 系統級 A/B 無退步 | **GO** → Stage 3 |
| 任何同事說「有問題」或任何檢查 FAIL | **NO-GO** → 回滾該機台 → 分析原因 |

### 產出
- 每位同事的 Stage 1 等級文件
- 跨角色比較報告
- Go/No-Go 彙總

## Stage 3：部門全部機台

### 目的
在部門內全面部署，由 IT 管理變更和支援。

### 機台
部門內所有使用 FlapsErp 的機台。

### 做什麼

| 步驟 | 誰做 |
|---|---|
| IT 備份所有機台的 config.ini | IT |
| IT 透過 GPO/SCCM/Intune 部署 Defender 排除 | IT |
| IT 透過 GPO 部署 GPU 偏好（HKCU→HKLM 或 per-user script） | IT |
| 每台機器跑 `flaps-safety-check.ps1` 確認 | IT 或代理 |
| 同事正常使用 | 同事 |
| 持續監控（`flaps-pilot-monitor.ps1`） | 排程 |

### 注意事項
- **逐步部署**：不要一次部署全部，分 2-3 批，每批之間觀察 1-2 天
- **Opt-out 可用**：任何同仁隨時可以要求回滾，IT 在 5 分鐘內處理
- **持續監控**：排程繼續跑，每週產出報告

### Go/No-Go 條件

| 條件 | 結果 |
|---|---|
| 部署後 1 週內無重大問題回報 + 持續監控無異常 | **GO** → Stage 4 |
| 超過 20% 機台回報問題 | **NO-GO** → 全面回滾 → 分析 |

## Stage 4：組織全面部署

### 目的
在其他部門也部署（如果適用）。

### 做什麼
- 複製 Stage 3 的經驗到其他部門
- 每個部門可能需要不同的硬體分支設定
- 監控持續

## 6. 時程估計

| 階段 | 時間 | 前提 |
|---|---|---|
| Stage 0 | 1-2 天 | 無 |
| Stage 1 | 5 天（含週末） | 1 位自願者 |
| Stage 2 | 7 天（含週末） | Stage 1 GO + 2-3 位自願者 |
| Stage 3 | 2-3 週（分批部署） | Stage 2 GO + 主管簽核 |
| Stage 4 | 持續 | Stage 3 GO |
| **合計** | **4-6 週** | — |

## 7. 風險矩陣（每個階段）

| 階段 | 風險 | 發生率 | 影響 | 回滾時間 |
|---|---|---|---|---|
| Stage 0 | 腳本在非標準環境失敗 | 中 | 無（不是同仁機器） | 不需要 |
| Stage 1 | 同事工作受影響 | 低 | 該同事的工作延遲 | < 1 分鐘 |
| Stage 2 | 多台同時出問題 | 低 | 多位同事工作延遲 | < 5 分鐘（每台獨立回滾） |
| Stage 3 | 大範圍問題 | 極低 | 部門工作受影響 | < 30 分鐘（批次回滾） |
| Stage 4 | 組織級問題 | 極低 | 組織工作受影響 | 依部署範圍 |

## 8. 同仁溝通（每個階段的開場白）

### Stage 1 對自願者說：
> 「我想在你下班前花 15 分鐘做一個小實驗。我會先備份你的 FlapsErp 設定，然後做一些 Windows 系統調整讓 FlapsErp 更快。你接下來 4 天正常工作就好。如果任何時候你覺得有問題，告訴我，我 1 分鐘內回滾。4 天後你告訴我有沒有覺得比較快，你決定要不要繼續。」

### Stage 2 對其他同事說：
> 「上週我們在 [同事名字] 的機器上做了優化，他說沒有遇到問題，而且 [具體操作] 從 X 秒變成 Y 秒。我想在你的機器上也做同樣的事。你只要正常工作一週，我們在背景量測。如果你覺得有任何問題，告訴我，我立刻回滾。」

### Stage 3 對部門說：
> 「我們已經在 [N] 台機器上驗證了優化，全部通過。現在要在部門全面部署。IT 會在下班時間執行，你隔天來的時候 FlapsErp 會跑得一樣或更快。如果你有任何問題，IT 會在 5 分鐘內回滾你的機器。」

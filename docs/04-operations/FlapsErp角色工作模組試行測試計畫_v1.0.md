# FlapsErp 角色工作模組試行測試計畫 v1.0
# 按角色與功能模組分開設計——每個角色的日常作業不同，量測方式也不同

> 日期：2026-11-13｜狀態：Draft（待同仁試行）
> 核心：**不是量 COM P50 或 RAM median，而是量「你點了按鈕之後多久看到結果」**
> 目標：讓每個角色在他們的日常工作中**親身感受到**改善

---

## 1. 角色定義與 FlapsErp 模組對應

### 財務人員（Accounting/Finance）

| FlapsErp 模組 | 日常作業 | 使用頻率 | 效能敏感度 |
|---|---|---|---|
| 應付憑單（FAS_AccountPayable） | 查詢憑單、新增/修改、匯出 | 每日多次 | 高（列表載入慢會卡工作） |
| 總帳（FAS_GeneralLedger） | 查詢分錄、月結 | 每日/月底 | 高（大量資料載入） |
| 財務報表（FAS_Reports） | 資產負債表、損益表匯出 | 每週/月底 | 高（報表渲染慢） |
| 銀行對帳（BankPay） | 付款媒體產生、對帳 | 每日/每月 | 中 |
| 網路瀏覽器 | 查銀行/稅務網站、回覆客人 | 每日 | 間接（RAM/GPU 競爭） |
| Outlook | 收發請款/通知郵件 | 每日 | 間接（RAM 競爭） |
| Excel | 對帳資料整理、報表前處理 | 每日 | 間接（RAM/CPU 競爭） |

**財務人員的多工情境**：
- 同時開：FlapsErp（2-3 分頁）+ Outlook + Excel + Chrome（3-5 分頁）
- 最痛的時刻：月底大量報表 + 同時回覆客人 + FlapsErp 切換分頁

## 3. 試行計畫（按角色分組）

### 3.1 試行環境需求

| 角色 | 機台需求 | 軟體需求 | 網路需求 |
|---|---|---|---|
| 財務人員 | 16 GB RAM；SSD；獨顯（hybrid） | FlapsErp + Outlook + Excel + Chrome | AP 可連線 |
| 物流人員 | 8+ GB RAM；SSD | FlapsErp + 物流商網站 | AP 可連線 |
| 門市人員 | 8+ GB RAM | FlapsErp POS | AP 可連線 |
| 主管 | 8+ GB RAM | FlapsErp + Office | AP 可連線 |

### 3.2 試行流程

```
第 1 週｜基線（尚未優化）
├── 財務人員 A 機：安裝 flaps-pilot-monitor.ps1（排程 30 分鐘）
│   → 正常使用 FlapsErp（應付憑單/報表/對帳）
│   → 自動收集：每次操作的回應時間
├── 物流人員 B 機：安裝同上
│   → 正常使用 FlapsErp（庫存/POS）
│   → 自動收集
└── 門市人員 C 機：安裝同上
    → 正常使用 FlapsErp（POS/庫存查詢）
    → 自動收集

第 2 週｜套用優化
├── 在 A/B/C 機上執行 flaps-optimize.ps1 -Action Optimize
├── 重啟 FlapsErp
└── 繼續收集數據（排程不變）

第 3 週｜比較
├── flaps-pilot-report.ps1 -SplitDate "<第 2 週開始日期>"
├── 產出：每個角色、每個操作的前後對照
└── 讓同仁看到數據：「你每天做的 X 操作，從 Y 秒變成 Z 秒」

第 4 週｜全面部署
├── 如果同仁滿意 → 在所有機台部署
├── 如果有問題 → 回滾並改善
└── 持續監控
```

### 3.3 每個角色的成功標準

| 角色 | 成功條件 | 怎麼判斷 |
|---|---|---|
| 財務人員 | 應付憑單開啟速度改善；月底報表不卡 | 數據 + 同仁說「比較快」 |
| 物流人員 | 庫存查詢改善；POS 交易不受影響 | 數據 + 同仁說「正常」 |
| 門市人員 | POS 交易穩定；尖峰時段不卡 | 數據 + 無客訴 |
| 主管 | 報表產出改善 | 數據 |

## 4. 試行計畫的工具支援

### 4.1 自動監控（flaps-pilot-monitor.ps1）

在每台測試機上註冊排程，每 30 分鐘自動收集：

| 收集項目 | 對應的使用者體感 |
|---|---|
| FlapsErp 行程數 | 「開了幾個功能」 |
| FlapsErp 總 RAM | 「ERP 佔了多少記憶體」 |
| COM P50 | 「POS/條碼回應速度」 |
| module→menu | 「登入後等多久」 |
| tab interval | 「切換分頁的間隔」（使用頻率指標） |
| report generation | 「報表產出時間」 |
| 系統 free RAM | 「還有多少空間給其他程式」 |
| 系統 CPU | 「機器忙不忙」 |
| 磁碟佇列 | 「磁碟是否為瓶頸」 |
| AP 回應 | 「網路/AP 是否為瓶頸」 |

### 4.2 報告產生（flaps-pilot-report.ps1）

```powershell
# 第 1 週結束後（基線報告）
flaps-pilot-report.ps1

# 第 2 週結束後（比較報告）
flaps-pilot-report.ps1 -SplitDate "2026-11-18"
```

### 4.3 排程註冊（flaps-pilot-setup.ps1）

```powershell
# 每台測試機執行一次
flaps-pilot-setup.ps1 -IntervalMinutes 30

# 如果要停止
flaps-pilot-setup.ps1 -RemoveTask
```

## 5. 同仁溝通（用他們的語言）

### 對財務人員說：
> 「我們做了一個系統優化，讓你打開應付憑單和匯出報表的速度變快。你不需要改變任何工作習慣，我們會在背景自動收集數據。兩週後我們給你看數據，如果你覺得沒有變快，我們立刻回滾。」

### 對物流人員說：
> 「我們做了優化讓庫存查詢更快。你的 POS 交易和條碼掃描不受影響。你正常工作就好，我們在背景量測。」

### 對門市人員說：
> 「POS 交易速度不會變——我們沒有動 POS 相關設定。我們優化的是系統資源分配，讓你在尖峰時段多人使用時不會卡。」

## 6. 角色相關的風險與注意事項

| 角色 | 風險 | 注意事項 |
|---|---|---|
| 財務 | 月底大量報表可能觸及 4 GB 上限 | 批次外移 Wellfit |
| 物流 | POS 交易不能有任何延遲 | POS 用 COM（不受 Defender 排除影響）；庫存查詢受 I/O 影響 |
| 門市 | 尖峰時段多人同時使用 | 需在尖峰時段量測（不是閒置時量） |
| 主管 | 報表渲染需要大量 RAM | 報表外移 Wellfit |
